# N-Puzzle 五人小组分工方案

## 项目目标与协作原则

本方案面向 N-Puzzle SRDP 项目，由 A、B、C、D、E 五位成员协作完成状态建模、搜索求解、启发函数、实验评估、可视化及项目汇报。分工按成员与模块组织，兼顾工作量和模块依赖。

各成员对所负责模块的实现、验证和说明文档负责。全组共用统一的棋盘状态和接口约定，按照 [开发规范](DEVELOPMENT.md) 进行分支开发、代码审核和集成。文中的代码位置均相对仓库根目录。

## 职责总览

| 成员 | 主要负责方向 | 核心交付物 | 协作与汇报职责 |
| --- | --- | --- | --- |
| A | 状态表示、基础操作、可解性判断 | 棋盘状态及工具接口、逆序数与可解性判定 | 优先交付基础接口；负责项目展示与口头汇报（pre） |
| B | 搜索容器、基础启发函数 | Open/Closed 容器、状态哈希、曼哈顿距离、汉明距离、空位距离 | 与 A、C 对齐状态去重和启发函数接口 |
| C | A*、IDA* 搜索内核 | 可运行的搜索流程、解路径文本输出 | 对接 A、B、D；向 E 提供路径文件；必要时协助双向 BFS |
| D | 不相交 PDB、数据库生成、性能实验 | PDB 启发函数、BFS/双向 BFS 生成与对比、随机用例、测试脚本与实验数据 | 与 C 联调高级启发函数；向全组提供测试用例与性能数据 |
| E | 可视化、文档与报告汇总 | 拼图动画、接口说明汇总、SRDP 报告、模块介绍和简历素材 | 负责汇报 PPT 制作，与 A 配合完成演示准备 |

## 成员职责与交付要求

### 成员 A：基础状态与可解性

- 实现统一的棋盘状态表示、文本打印、状态拷贝、合法移动、空格位置查找等基础能力。
- 实现逆序数计算和 N-Puzzle 可解性判断，明确不同棋盘尺寸及目标状态下的判定规则。
- 为全组提供状态生成、合法性校验和可解性判定接口，并说明棋盘编码、空格表示和动作方向。
- 优先完成基础模块，支持 B、C、D 的开发与调试。
- 负责项目展示与口头汇报（pre），组织讲述项目目标、实现思路、实验结论与演示内容；与 E 对齐 PPT 和讲述顺序。

主要代码位置为 `WattAi/src/stud/g01/problem/npuzzle/`，围绕 `PuzzleBoard` 和 `NPuzzleProblem` 补齐基础能力。交付内容包括基础代码、接口说明和典型验证用例。

### 成员 B：搜索容器与基础启发函数

- 实现 Frontier（Open 优先队列）、Explored（Closed 集合）及相关容器封装。
- 与 A 共同确定状态相等和哈希规则，完成搜索去重、重复状态处理及更优结点更新。
- 实现曼哈顿距离、汉明距离（错位数）和空位距离三类基础启发函数，说明计算规则及适用范围。
- 向 C 提供统一的队列、集合和启发函数接口，并与 D 对齐后续 PDB 的接入方式。

主要代码位置为 `WattAi/src/stud/g01/queue/` 及 NPuzzle 启发函数相关实现；通过现有 `Frontier`、`Predictor` 接口接入框架。当前仓库使用 Java，容器封装采用 Java 集合。交付内容包括容器实现、基础启发函数、接口说明和验证用例。

### 成员 C：A* 与 IDA* 搜索内核

- 基于现有框架完成 A* 搜索流程的接入、完善与验证，实现 IDA* 迭代加深搜索。
- 对接 A 的状态表示、B 的搜索容器和基础启发函数，形成完整求解流程。
- 处理 IDA* 递归阈值更新、剪枝、路径重复检查和终止条件，完成解路径回溯与保存。
- 输出统一格式的解路径文本文件，供 E 的可视化模块读取。
- 与 D 联调 PDB 启发函数，支持不同算法与启发函数的实验对比；D 工作量较大时，协助双向 BFS 的实现与验证。

主要代码位置为 `WattAi/src/stud/g01/solver/`、`WattAi/src/stud/g01/runner/` 及解路径输出相关实现。A* 复用并完善现有 `BestFirstSearcher` 接入，IDA* 在 `IdAStar` 中实现。交付内容包括可运行的求解流程、路径文件格式说明、示例路径和正确性验证结果。

### 成员 D：高级启发函数与实验评估

- 实现不相交模式数据库（disjoint Pattern Database，PDB）启发函数，明确模式划分、状态编码、代价计算和查询方式。
- 实现 PDB 生成逻辑，开展 BFS 与双向 BFS（Bi-BFS）的实现及对比，记录扩展结点数和运行时间等指标。
- 生成随机测试用例并过滤不可解状态，提供全组共享的调试与实验输入；Java 实现可使用 `Collections.shuffle` 或等价方式。
- 编写批量性能测试脚本，对 A*、IDA* 及不同启发函数进行对比，整理可复现的实验数据。
- 复用 A 的状态表示，与 C 对齐搜索及统计接口，向 E 提供图表所需的数据与实验结论。

PDB 通过统一启发函数接口接入求解器。新增实验结果按开发规范放入 `benchmarks/runs/<实验名称>/`，记录版本、输入、运行命令、算法、启发函数及测试环境。交付内容包括 PDB 生成与查询代码、生成参数说明、随机测试工具、性能脚本和实验数据。

### 成员 E：可视化、报告与汇报 PPT

- 使用 SFML、Unity 或团队确定的可视化方案，读取 C 输出的解路径文本，实现拼图动画播放。
- 与 C 提前约定路径文件格式，通过文件交接搜索结果，保持可视化与搜索内核独立。
- 汇总各成员的接口说明、模块介绍、实验截图和数据，整理 SRDP 项目报告。
- 整理项目成果和各成员贡献，形成可用于简历的项目描述。
- 负责汇报 PPT 的结构、排版、图表和演示素材制作，与 A 对齐讲述内容并完成汇报演练。

交付内容包括可视化程序及使用说明、演示素材、项目报告、汇报 PPT 和模块贡献说明。A、B、C、D 负责提供各自模块的准确描述、验证结果与必要截图，E 统一整理。

## 依赖与推进安排

| 阶段 | 主要工作 | 完成条件 |
| --- | --- | --- |
| 基础接口确定 | A 优先交付状态表示、基本操作与可解性判断；全组确认接口 | B、C、D 能共用同一套状态表示开展开发 |
| 基础搜索集成 | B 完成容器和基础启发函数；C 对接并完成 A*、IDA* | 简单可解用例能输出合法解路径，无解状态能按约定处理 |
| 高级启发与实验 | D 完成 PDB、生成算法和随机测试工具；C 协助接入及联调 | 能在一致输入和统计口径下比较算法、启发函数和数据库生成方式 |
| 可视化与成果汇总 | E 对接路径文件并制作动画、报告和 PPT；A 准备汇报 | 演示、报告、PPT 与实际代码及实验结果一致 |

以上阶段表示接口交付和集成顺序。接口确定后，各模块可并行推进：D 可提前设计模式划分和测试工具，E 可依据示例路径准备可视化和 PPT 框架。

## 模块交接与共同约定

- **状态接口：** A 统一状态结构；B 的哈希与去重规则与 A 保持一致，其他成员复用该结构。
- **搜索接口：** B 与 C 共同确认 Open/Closed 行为、重复状态更新方式及启发函数调用约定；IDA* 的路径去重和剪枝由 C 按算法特点实现。
- **路径文件：** C 与 E 在实现前确定棋盘尺寸、初始状态、动作或逐步棋盘、目标状态及步数的表达方式，并提供一个可读取的示例。
- **PDB 接入：** D 与 B、C 共用启发函数接口，保证实验时能切换基础启发函数与 PDB，进行统一对比。
- **实验数据：** D 提供随机用例和实验汇总，各成员复用用例验证模块；E 根据实际数据制作图表和报告，A 在汇报中说明结果。
- **工作量调整：** D 是高级启发与实验的主要负责人；需要分担时，由 C 协助双向 BFS，D 继续负责整体生成方案与实验汇总。
- **汇报协作：** A 负责 pre 的讲述与现场展示，E 负责 pre 的 PPT 制作；全体成员提供模块材料并参与内容核对和演练。
